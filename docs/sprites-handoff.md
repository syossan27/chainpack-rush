# スプライト／モーション制作の引き継ぎ

絵を作る人（PixelLab での生成・PR 作成）向けのメモ。ゲームへの組み込みは作業ブランチ側で済んでいるので、ここに書いた形で画像と設定を出せば、登録するだけで戦闘で動く。

## プロジェクト

- 30秒のオート連鎖ハクスラ（TypeScript + Phaser 3 + Vite + Capacitor）
- スプライトの登録: `src/data/sprites.ts`（アニメごとに frameWidth / frameHeight / originX / originY を持てる）
- 素材の置き場: `assets/sprites/...`（例: `assets/sprites/enemies/slime/`）。数値の記録は `assets/raw/...`
- パレット: `assets/palette.hex`（32色）
- 回答・PR の説明は日本語で

## PR の出し方（重要）

- **ベースは `claude/zealous-newton-kv0quu`**（PR #5 がマージされたら `main`）。PR #4 / #6 / #8 の上に積まない。
  - #4・#6・#8 の画像と設定は、すでに作業ブランチに取り込み済み（#4・#6・#8 は閉じてよい）。
  - 古いブランチの上に積むと `src/data/sprites.ts` などがぶつかる。
- 1つの PR には1キャラ（または1つの必殺技）の画像・`*_export.json`・プレビューだけ入れる。`sprites.ts` の登録は書いてもよいが、下の「登録の書き方」に合わせる。

## 絵柄の方針

- ヒーロー: ちびキャラの64pxの騎士。等身を上げたり、リアルにしたりしない。
- スライム: 大福のような丸み、縦線の目、口なし、少し左向き（登録済み）。
- 狼: スライムを絵柄の見本に、色を8色にしぼったシンプルな版（丸い体・点の目・ほっぺ・丸いしっぽ）。これからの雑魚はこの「シンプルでポップ」寄りに合わせる。
- ゴブリン: PixelLab で作った v3c（オリーブ色の肌、レザーベスト、こん棒を左肩に担ぐ、64pxキャンバスで身長約42px）。
- 敵は左向き（右から来て、左にいるヒーローへ向かう）。体だけでなく、顔（目・鼻）と武器の向きまで確かめる（ゴブリンは顔が右を向いていて作り直した）。
- ポップでシンプル、1pxの暗い輪郭、少ない色数。
- 雑魚は可愛い寄り、ボスはちび体型のまま、光る目・冠・鎧などでカッコよく。
- 32pxの手描きで複雑なキャラを描くと形が崩れるので、複雑なものは PixelLab で作る。

## フレーム規約（必ず守る）

- 基本のフレームは 64×64、地面は y=55、原点は (32/64, 56/64)。
- ボスは 96×96、地面は y=87、原点は (48/96, 88/96)。攻撃は 128×96 で原点X を 80/128 にする。
- 攻撃で横にはみ出すものは 96×64 にして、原点X を 64/96 にする。
- フレームを中央に寄せ直さない（足元の位置がずれるため）。
- アルファは 0 か 255 だけ。半透明のゴミや白いにじみを残さない。
- ゲーム内では2倍の最近傍補間で表示する。
- アニメごとに、横並びのストリップPNG、プレビュー用GIF、`*_export.json` を作る。
  - JSON の項目: file, frameWidth, frameHeight, frames, originX, originY, originPx, fps, loop, groundY, note
- 目安:

  | アニメ | コマ数 | fps | ループ | 備考                                             |
  | ------ | ------ | --- | ------ | ------------------------------------------------ |
  | move   | 6      | 10  | する   |                                                  |
  | attack | 6      | 12  | しない |                                                  |
  | defeat | 6      | 10  | しない | 最後のコマはうすく残るが、ゲーム側で再生後に消す |

- 雑魚は move / attack / defeat、ボスは idle / attack / defeat。ゲーム側のキーは `death`（ファイル名は defeat のままでよい）。

## ゲーム側の再生（実装済み）

- 敵: ふだんは `move`（なければ `idle`。ボスは idle）をループ（開始コマはばらばら）。ヒーローに当てたときに `attack` を1回再生して ふだんのループに戻る。倒されたら、その場で `death` を再生して消える。アニメの速さはゲームの倍速に合わせる。
- 本素材のある敵には、ゲーム側の上下の揺れを付けない（揺れはアニメで表現する）。
- 必殺技: 技の id ごとに `special_<id>` を再生する（`crimson` / `thunder` / `frost` / `triple` / `whirl`、5つとも登録済み）。`impactFrame`（決めのコマ）に合わせて、大きな演出とダメージを出す。
- ヒーローの待機の足の浮きは修正済み（拠点・ラン画面とも）。

## 登録の書き方（`src/data/sprites.ts`）

スライムの登録を見本にする。敵では次の2つを必ず書く。

- `facesLeft: true`: 本素材は左向きなので反転しない（仮素材は右向きなので反転している）。
- `bodyHeight`: 足元から頭のてっぺんまでの高さ（コマの px）。HPバーとダメージ数字の位置に使う。スライムは 26。

```ts
goblin: {
  ...unit('goblin', GOBLIN, 48),
  bodyHeight: 42,
  facesLeft: true,
  anims: {
    move:   { file: 'enemies/goblin/goblin_move.png',   frames: 6, fps: 10, loop: true,  frameWidth: 64, frameHeight: 64, originX: 32 / 64, originY: 56 / 64 },
    attack: { file: 'enemies/goblin/goblin_attack.png', frames: 6, fps: 12, loop: false, frameWidth: 96, frameHeight: 64, originX: 64 / 96, originY: 56 / 64 },
    death:  { file: 'enemies/goblin/goblin_defeat.png', frames: 6, fps: 10, loop: false, frameWidth: 64, frameHeight: 64, originX: 32 / 64, originY: 56 / 64 },
  },
},
```

必殺技は `special_<技のid>` に `impactFrame`（0 始まり）を足す。

## PixelLab

- トークンは環境変数 `PIXELLAB_API_TOKEN`。画面に出さず、ファイルにも保存しない。
- Tier 1 プラン（毎月10日にリセット、2,000回/月）。
- 生成の前に、ユーザーの承認を1種類ずつ取る。
- キャラの生成: generate-image-v2（64px）がいちばんきれいだった。ヒーローの画像をスタイル参照に渡す（色は真似させず、輪郭と塗りだけ）。
- モーション: animate-pixminimax で、元のキャラを最初と最後のコマに指定する。コマ数は4の倍数しか指定できないので、9コマ作ってから良い6コマを選ぶ。
- 1回で決まることは少ないので、seed を変えて何本か作って比べる。
- inpaint（部分修正）は背景が白くなったり、パレット外の色が混ざったりしやすい。結果を必ずチェックする。
- よくある失敗: 途中のコマで持ち物が消える、キャラが縮む、足が1px浮く、耳などに白いゴミが出る。

## 確認のしかた

- 作るたびに、8倍のプレビュー、2倍のGIF、地面線入りのシートを出して、全コマを自分の目で見る。
- 特に、足（切れていないか、y=55 に付いているか）、持ち物、目の状態を確認する。
- 目を閉じる表現は、白目や瞳のピクセルを全部肌色で塗り直してから線を描く。プログラムでも、目の範囲に白目の色が残っていないか確かめる。
- 自分で確認してからユーザーに見せる。
