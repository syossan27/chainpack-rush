# ランキング用サーバー（Firebase）の準備

2週替わりの挑戦とエンドレス（月ごとのシーズン）のランキングを、Firebase で動かすための準備と仕組みのまとめ。

- あなたにやってもらうこと: 「1. 準備」の手順（Google アカウントでの作業）。
- Claude が書くもの: サーバー側のコード（スコアの受け付け・再生による確認・ランキングの集計・報酬の配布）と、ゲーム側の送受信。

## 1. 準備（あなたの作業）

### 1-1. Firebase のプロジェクトを作る

1. <https://console.firebase.google.com/> を Google アカウントで開く。
2. 「プロジェクトを追加」で、名前を入れる（例: `chainpack-rush`）。Google アナリティクスは「有効」にしておくと、あとで遊ばれ方の計測にも使える。
3. 作成が終わるまで待つ（1分ほど）。

### 1-2. 従量課金のプラン（Blaze）にして、予算アラートを付ける

サーバーで処理を動かす機能（Cloud Functions）を使うには、従量課金のプランが必要。無料枠は従量課金のプランにも付いているので、利用者が少ないうちは請求は0円。

1. コンソールの左下「Spark プラン」→「アップグレード」→「Blaze」。支払い用のカードを登録する。
2. 予算アラートを作る: Google Cloud コンソールの「お支払い」→「予算とアラート」→「予算を作成」。
   - 例: 月 1,000円。50%・90%・100% でメール通知。
   - 予算アラートは通知だけで、自動では止まらない。想定外に増えたら、通知を見て連絡してください（上位の記録だけ確かめる、などに切り替えます）。

### 1-3. 使う機能をオンにする

コンソールの左のメニューから、順に設定する。

1. **Authentication（ログイン）**: 「始める」→「ログイン方法」→「匿名」を有効にする。
   - プレイヤーに登録やログインをしてもらう必要はない。端末ごとに自動で匿名のIDが付く。
2. **Firestore Database（データの保存）**: 「データベースを作成」→ 場所は **asia-northeast1（東京）** → 「本番環境モード」で開始。
3. **App Check（不正な送信を防ぐ）**: 「始める」→ アプリを登録するときに、Android は Play Integrity、iOS は App Attest を選ぶ。
   - アプリの登録（1-4）のあとで設定する。ストアに出す前でもよい。

### 1-4. アプリを登録して、設定値を教える

1. プロジェクトの設定（歯車）→「マイアプリ」で、次の3つを追加する。
   - **Web アプリ**（開発中の確認用）
   - **Android アプリ**: パッケージ名 `com.chainpack.rush`
   - **iOS アプリ**: バンドル ID `com.chainpack.rush`
2. Web アプリの「SDK の設定と構成」に出る `firebaseConfig`（`apiKey`・`authDomain`・`projectId`・`appId` など）を、チャットに貼ってください。
   - この値は公開しても問題ない種類のもの（アプリに埋め込まれる）。秘密の鍵ではない。
3. Android 用の `google-services.json` と、iOS 用の `GoogleService-Info.plist` をダウンロードしておく。ネイティブのビルドのときに `android/app/` と `ios/App/App/` に置く。

### 1-5. サーバーへの反映（デプロイ）の方法を決める

サーバー側のコードを Firebase に反映するには、次のどちらか。

- **A. 自分の PC から反映する（かんたん）**
  1. Node.js を入れて、`npm install -g firebase-tools`
  2. `firebase login`（ブラウザで Google アカウントにログイン）
  3. リポジトリで `firebase deploy --only functions,firestore`
  - コードを変えるたびに、この手順を実行する。
- **B. GitHub から自動で反映する**
  1. Google Cloud コンソールで、デプロイ用のサービスアカウントを作り、鍵（JSON）を発行する。
  2. GitHub のリポジトリの Settings → Secrets に `FIREBASE_SERVICE_ACCOUNT` として登録する。
  3. main に入ったときに自動で反映する設定（GitHub Actions）は Claude が書く。
  - 鍵はチャットに貼らないこと。GitHub の Secrets にだけ置く。

最初は A がおすすめ。慣れたら B に切り替えられる。

## 2. 仕組み

### 2-1. 流れ

1. ゲームは起動時に匿名でログインする（ID は端末ごと）。
2. 挑戦・エンドレスで自己ベストを更新したら、「乱数の種・配置・装備・消耗品を使ったタイミング・結果」をサーバーへ送る。
3. サーバーは同じ戦闘の計算（ゲームと同じ `src/core`）で、そのランを最初から再生する。結果が一致したときだけ記録する（改ざんした記録ははじく）。
4. 数分ごとに、上位100人と順位帯の境目をまとめたデータを作り直す。ゲームはそれを1回読むだけ。
5. シーズン（挑戦は2週間、エンドレスは1か月）が終わったら、順位帯ごとに報酬を配る。報酬は次に起動したときに受け取る。

### 2-2. 再生で確かめられる理由

- 戦闘の計算は、60分の1秒ずつ進む決まった計算で、同じ入力からは必ず同じ結果になる（乱数も種から作る）。
- プレイヤーの操作は「消耗品をいつ使ったか」と「撤退」だけなので、送るデータは小さい。
- 装備も一緒に送るので、持っていない装備を使った記録もはじける（エンドレスは自分の装備、挑戦は決められた装備）。

### 2-3. 保存するデータ（Firestore）

| コレクション                       | 中身                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `players/{uid}`                    | 表示名、称号、受け取っていない報酬                                       |
| `seasons/{seasonId}`               | 種類（挑戦・エンドレス）、期間、条件（挑戦）、状態                       |
| `seasons/{seasonId}/entries/{uid}` | 自己ベスト（スコア・到達周回・合計ダメージ）、再生確認の結果、送った日時 |
| `seasons/{seasonId}/board/top`     | 上位100人と、順位帯の境目のスコア（数分ごとに作り直す）                  |

- 書き込みはサーバー（Cloud Functions）からだけにする。ゲームから直接は書けないルールにする。
- 表示名は、決まった単語の組み合わせから選ぶ形にする（自由入力にしない。不適切な名前を防ぐ）。

### 2-4. 報酬（案）

順位帯で配る（上位の人だけが強くならないように、強さに関係しないものにする）。

| 順位帯         | 報酬                                                               |
| -------------- | ------------------------------------------------------------------ |
| 上位1%         | 称号・特別なオーラの色・限定のアーティファクト（見た目が違うだけ） |
| 上位10%        | 称号・オーラの色                                                   |
| 上位50%        | 称号                                                               |
| 参加した人全員 | ゴールドとレア以上確定の宝箱                                       |

## 3. 費用の目安（月額）

前提: 自己ベストを更新したときだけ送る（1人1日3回ほど）、サーバーで再生して確かめる（1回0.1〜0.3秒）、ランキングはまとめたデータを1回読む。1ドル150円。

| 毎日遊ぶ人数 | 月額の目安      | 内訳                                  |
| ------------ | --------------- | ------------------------------------- |
| 1,000人      | 0円             | 無料枠の中                            |
| 1万人        | 0〜500円        | 書き込みが無料枠を少し超える          |
| 10万人       | 5,000〜15,000円 | 書き込み（月900万回ほど）と再生の計算 |

- いちばん費用がかかるのは再生による確認。人数が増えたら「上位の記録だけ確かめる」に切り替えると大きく減らせる。
- 毎日1万人の規模なら、報酬つき広告の収入は月数十万円の見込みなので、サーバー代は小さい。

## 4. 作ったもの（コードは準備済み）

| 場所                      | 中身                                                                                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `src/core/replay.ts`      | ランの再生（同じ設定と操作から、同じ結果になるか）                                                                                |
| `src/core/ranking.ts`     | 送る記録の形と、サーバーでの確認（装備・強化の範囲、挑戦の制限、再生して結果が一致）                                              |
| `src/core/names.ts`       | 表示名（決まった言葉の組み合わせ）と、報酬の順位帯                                                                                |
| `functions/src/index.ts`  | Cloud Functions: `submitScore`・`setName`・`myRank`・`claimRewards`、5分ごとの上位表 `buildBoards`、毎日の報酬配布 `grantRewards` |
| `firestore.rules`         | ゲームから直接は書けない。読めるのは上位の表と、自分の情報だけ                                                                    |
| `src/platform/ranking.ts` | ゲーム側の送受信（設定値が入るまでは何もしない）                                                                                  |
| `src/config/firebase.ts`  | **ここに firebaseConfig を入れる**                                                                                                |

- 戦闘のべき乗は掛け算の繰り返しにした（端末の Safari とサーバーの Node で、計算がぴったり同じになるように）。
- エンドレスは自分の装備で遊ぶので、持っていない装備を「持っている」と偽った記録までは見抜けない（装備の強さ・強化の段は正しい範囲かを確かめる）。上位がおかしくなったら、`rejected` コレクション（はじいた記録）と合わせて見直す。

## 5. 設定値をもらったあとの流れ

1. `src/config/firebase.ts` に firebaseConfig を入れる（Claude）。
2. `.firebaserc` のプロジェクト ID を合わせる（Claude）。
3. サーバーへ反映（あなた。1-5 の A なら）:
   ```bash
   cd functions && npm install && cd ..
   firebase deploy --only functions,firestore
   ```
4. 試遊版で、挑戦・エンドレスの記録が送られて、ランキングに出るかを確かめる。
5. App Check を設定したら、`functions/src/index.ts` の `ENFORCE_APP_CHECK` を `true` にして、もう一度反映する。

## 6. 手元での通し確認（Firebase エミュレーター）

本物のサーバーに反映する前に、手元の偽のサーバー（エミュレーター）で、送信 → 記録 → 順位 → 不正な記録の拒否までを確かめられる（Java が必要）。

```bash
cd functions && npm install && npm run build && cd ..
npx firebase emulators:exec --only functions,firestore,auth --project demo-chainpack-rush "npx tsx tools/rankingE2E.ts"
```

`ALL OK` と出れば通っている。5分ごとの上位表と毎日の報酬配布は、エミュレーターでは動かない（スケジュール実行のため）ので、反映後に確かめる。
